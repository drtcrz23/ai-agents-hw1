# HW1: сравнение Qwen3.5-9B Q4 и Q8

Сравниваются Q4_K_M и Q8_0 через LM Studio/Bionic (llama.cpp, Metal).
Компьютер: Apple M4 Pro, 48 ГБ памяти, macOS 26.2.

## Запуск

Включить локальный сервер LM Studio на `http://127.0.0.1:1234`.
Обе модели должны быть скачаны. Загрузка и выгрузка выполняются автоматически;
второй терминал не нужен. Команды выполнять по очереди.

```bash
# Только показать план; модель не запускается
./run.sh q8 speed --plan

# Один проверочный запрос с прогревом
./run.sh q8 smoke

# Скорость: 128, 1024, 4096 токенов, по три повтора
./run.sh q4 speed
./run.sh q8 speed

# Контекст: 1К–32К, по три повтора
./run.sh q4 context --lengths 1024 2048 4096 8192 16384 32768
./run.sh q8 context --lengths 1024 2048 4096 8192 16384 32768

# Отдельно проверить следующую ступень
./run.sh q4 context --lengths 65536
```

**Без `--plan` команда действительно запускает измерения.** `--execute` больше не нужен.
Если основной процесс не определяется автоматически, добавить `--memory-pid PID`.
По умолчанию `context` использует готовые ступени 1К–64К и останавливается при ошибке.
При `--lengths` можно выбирать длины, для которых есть файлы `prompts/input_*.txt`.

`run.sh` - короткая оболочка. Например, `./run.sh q8 speed` вызывает:

```bash
./scripts/python.sh scripts/benchmark.py --model q8 --mode speed
```

Параметры генерации, число повторов, таймаут и ключи моделей - в `experiment.json`.
Вручную переключать квантование в интерфейсе при автоматическом запуске не требуется.
Скрипт откажется выгружать другой или занятый экземпляр модели.

## Как устроен код

- `scripts/benchmark.py`: читает готовые промпты, выполняет цикл по длинам и повторам,
  записывает результаты
- `scripts/common.py`: отправляет потоковый HTTP-запрос, измеряет время и RSS,
  вычисляет медианы
- `scripts/lifecycle.py`: загружает точный вариант модели через SDK и проверяет настройки
- `scripts/report.py`: строит таблицы и четыре графика из выбранных логов
- `scripts/audit_runtime.py`: дополнительная проверка обработки полного входа по runtime-логам

Основной цикл: **выгрузка -> загрузка -> короткий прогрев -> измеряемый запрос -> запись**.
Он повторяется три раза для каждой длины. Каждый новый запуск создаёт отдельные логи.

## Методика

Одинаковые тексты из `prompts/` используются для обоих квантований. Это синтетические
записи о библиотеке и просьба описать риски и предложить улучшения. SHA-256 проверяет,
что сохранённый текст не изменился. Фактическую длину входа сообщает сервер.
В наших прогонах она на два токена больше целевой: 130, 1026, 4098 и т. д.

Перед каждым замером модель перезагружается для сброса предыдущего контекста.
Отдельный прогрев: `Write a cheerful four-line poem about a red balloon.`
Загрузка и прогрев не входят в медианы. Одновременно обрабатывается один запрос.

Фиксированы temperature=0, top_k=1, top_p=1, min_p=0, repeat_penalty=1,
reasoning=off, максимум 256 выходных токенов. Таймаут полного запроса - 120 с.
Для скорости окно 8192; для контекста - целевая длина входа плюс 512 под ответ и шаблон.

- TTFT: от отправки HTTP-запроса до первого непустого текстового события SSE.
- Latency: от отправки до `chat.end`.
- Tokens/sec: серверная статистика генерации, не число SSE-фрагментов.
- Память: RSS основного процесса и его потомков каждые 100 мс
- Три успешных повтора образуют стабильную ступень; в таблицах - медианы

## Полученные результаты

[Отчёт с таблицами и графиками](results/report.md).
Q4 в тесте скорости генерировала 36,93–38,29 токенов/с, Q8 - 25,73–26,39 токенов/с.
Обе конфигурации прошли 1К–32К по три раза. При входе 32770 токенов TTFT составил
93,44 с для Q4 и 90,14 с для Q8; максимальный наблюдаемый RSS - 8,01 и 11,56 ГиБ.
Q4 на 64К превысила 120 с. Q8 выше 32К не проверялась: её аппаратный максимум не установлен.

Все прогоны выполнены от зарядки, с одинаковыми параметрами генерации и версией движка. Фоновая нагрузка могла различаться. Окружение каждого прогона сохранено в его `environment.json`.

В отчёте используются прогоны от 30 сентября 2026 года.

## Файлы результатов и воспроизведение отчёта

Каждый запуск создаёт `logs/<дата-модель-режим>/`: `run.log` (JSON-строка на запрос
и итоговый блок), `summary.json`, `environment.json`, события `*-stream.json`,
отсчёты `*-memory.json`, настройки `*-load.json`.

```bash
# Перестроить отчёт по сохранённому списку results/selected_runs.json
./scripts/python.sh scripts/report.py

# Для новых прогонов указать их каталоги явно
# ./scripts/python.sh scripts/report.py logs/КАТАЛОГ_1 logs/КАТАЛОГ_2

# Дополнительный аудит при наличии исходных серверных логов
./scripts/python.sh scripts/audit_runtime.py
```

Все 54 успешных измерения сопоставлены с runtime-таймингами полного входа:
`results/runtime-input-audit.json`
## Установка на новом окружении

Скачать `Qwen3.5-9B-Q4_K_M.gguf` и `Qwen3.5-9B-Q8_0.gguf` из
`lmstudio-community/Qwen3.5-9B-GGUF`. Проверить пути моделей в `experiment.json`.

```bash
DYLD_LIBRARY_PATH=/opt/homebrew/opt/expat/lib python3.12 -m venv .venv
./scripts/python.sh -m pip install -r results/requirements-lock.txt
```

Оболочка `python.sh` добавляет CLI LM Studio в PATH и обходит локальный конфликт libexpat.
