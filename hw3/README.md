# HW3 - Coding-агент (ReAct)

Агент, который сам решает экспериментальную задачу: читает условие, пишет код,
запускает его, чинит ошибки и сверяет метрику с ожидаемым диапазоном.

## Запуск

```bash
cd hw1/hw3
python3 run_agent.py --task tasks/puzzle-8
```

Требования: LM Studio с моделью `qwen/qwen3.5-9b` (reasoning выключен в UI),
сервер на `http://127.0.0.1:1234/v1`. Стек тот же, что в hw2.

## Структура

```
hw3/
├── run_agent.py      # ReAct-цикл агента
├── common.py         # клиент к LM Studio (stdlib, без зависимостей)
├── README.md
└── tasks/puzzle-8/   # задача + артефакты
    ├── task.md       # условие задачи
    ├── expected.json # метрика и ожидаемый диапазон
    ├── experiment.py # код, написанный агентом
    ├── train.log     # лог эксперимента
    ├── agent.log     # лог шагов агента
    └── REPORT.md     # отчёт, написанный агентом
```

## Как работает

1. `run_agent.py` читает `task.md` + `expected.json` из папки задачи и кладёт их
   в стартовый промпт.
2. ReAct-цикл: модель вызывает инструменты, инструмент возвращает результат/ошибку,
   модель реагирует (чинит код, перезапускает). До MAX_STEPS шагов.
3. Инструменты:
   - `read_file` / `write_file` - файлы только внутри папки задачи (защита от
     выхода наружу через проверку `parents`, а не строкового префикса);
     повторная запись идентичного содержимого отсеивается (анти-луп);
   - `run_python` - `subprocess` с таймаутом; после успешного запуска инструмент
     сам парсит строки `METRIC <name> <value>`, сравнивает с `expected.json`,
     проверяет, что `train.log` кончается финальной summary-строкой, и возвращает
     модели вердикт PASS/FAIL вместе с выводом. Отсутствующая METRIC-строка -
     это FAIL, а не «молчаливый пропуск».
4. Завершение: только когда метрики PASS и `REPORT.md` написан.

**Ограничения:** `MAX_STEPS = 35` шагов, `RUN_TIMEOUT = 120с` на один запуск
эксперимента, `TOTAL_TIMEOUT = 30 мин` на всю сессию.

## Задача: оптимальный решатель восьминашек

`tasks/puzzle-8`: сгенерировать 100 случайных решаемых позиций 3×3 (seed 42,
решаемость через чётность числа инверсий), решить каждую оптимально (A* с
манхэттенской эвристикой), верифицировать каждый раствор независимым
применением ходов (с проверкой границ), писать прогресс в `train.log`
(строка на позицию + финальная summary-строка), вывести метрики.
Ожидание: `avg_moves ∈ [20, 24]` (средняя длина оптимального решения случайной
восьминашки - 22 хода), бонус - `solved_rate = 1.0`.

## Результаты финального прогона

| Параметр | Значение |
|---|---|
| Шагов агента | 12 из 35 |
| Время сессии | 236 с |
| Токены | 97 708 prompt + 6 856 completion |
| `avg_moves` | 22.33 - PASS (диапазон [20.0, 24.0]) |
| `solved_rate` | 1.0 - PASS |
| Запуск эксперимента | 1.1 с на 100 позиций |

Ход сессии по `agent.log`:
1. Чтение условия -> `write_file experiment.py` -> первый запуск упал (exit 1)
   (Полный traceback агент получил через ответ инструмента `run_python`,
   `agent.log` фиксирует только код завершения и время.)
2. Агент исправил код, перезапустил -> PASS (avg_moves=22.33, solved_rate=1.0)
3. Агент перечитал `train.log` и свой `experiment.py`, переписал код
   (самопроверка) и перезапустил -> снова PASS.
4. `REPORT.md` -> финальное сообщение

Т.е. цикл «действие -> результат -> исправление» отработал честно: одна ошибка
была допущена и исправлена самой моделью в ходе сессии.

## Логи

- `agent.log` - по одной строке на шаг:
  `[время] step N | tool=... | args=... | result/error`, плюс запись о каждом
  запуске эксперимента (`run record: exit=... time=...s`).
- `train.log` - пишется самим `experiment.py`: строка на позицию
  `puzzle i/100 moves=<len> time_ms=<t>` и финальная
  `Summary solved=<n>/100 avg_moves=<x>` последней строкой.

## Замечания

- `time_ms` в `train.log` - честное elapsed-время решения конкретной позиции
  (замер `time.perf_counter()` вокруг `solve()`). Агент допустил здесь ошибку
  в первых двух версиях (писал Unix-таймстамп), она исправлена, эксперимент
  пересчитан локально: метрики не изменились (avg_moves=22.33, solved_rate=1.0,
  ~1 с на 100 позиций).
- `solved_rate` агент считает честным счётчиком (`solved_count / 100`),
  а не хардкодом.
- Метрика сравнивается дважды: инструмент `run_python` возвращает вердикт в
  модель (для цикла исправления), и финальная сверка в REPORT.md делается
  самой моделью.
